Family AI Assistant

A mobile-first family operations assistant. It keeps the household's documents, expiries and renewals in one calm vault, surfaces per-child school tasks pulled out of real communications, and answers natural-language questions through a server-side AI concierge grounded only in the family's own data. Built in Expo / React Native; backend on Vercel serverless + Supabase Postgres (row-level security) + OpenRouter.

Design language — Calm Concierge. Warm paper surfaces, a single clay accent (#B5654A), Fraunces serif headings over Inter body text, Phosphor icons and soft rounded cards. Member colours are reserved strictly for identity; clay carries every interactive and selection state. Every mockup below is rendered from the real screen source and the seeded Pacheco family — Diogo, Alana, Bella, Noah, Ayla — with the POC reference date of 19 May 2026.
How to read this. Use the chips above or the ←/→ arrows to page through every screen. Each screen is grouped Auth → Core tabs → Detail & flows → Profile, shown in a phone frame with a written explanation of what it does, the data it shows, and any AI behaviour. Nine screens are Built; the Profile & Settings panels are Planned.

Answered state · markdown reply

Natural-language questions, grounded answers

A chat concierge. The empty state offers tappable suggestion chips; once a question is asked it becomes a clay user bubble, and the assistant replies in a paper bubble with markdown rendering (bold, bullet lists) under a "Concierge" label. A "Thinking…" state shows while the server works.

Key elements
  • Clay sparkle orb + "How can I help your family?"
  • Four suggestion chips referencing the real children
  • Right-aligned user bubbles, left-aligned markdown assistant bubbles
  • Rounded composer with clay send button
AI & backend
Each question hits /api/ai/ask, a server-side tool-calling agent. It can only read the signed-in family's own rows (documents, tasks, communications, school results) — grounded strictly in their data, never another family's. The OpenRouter key lives only on the server; the app just sends the question and renders the answer.

Review & save

Photo in, structured document out

A modal three-step flow for adding a document. Capture a photo or pick one from the library; the assistant reads it; then the family reviews and edits the extracted fields before saving to the vault.

The three phases
  • Capture — Take photo / Choose from library
  • Extracting — image preview + "✨ Reading document…" spinner
  • Review — confidence pill, editable title/number/expiry, category & owner chips, Save to vault
AI & backend
The captured image is sent to /api/ai/extract, a server-side multimodal call that returns validated structured fields (title, number, category, owner, expiry) plus a confidence score. The owner chips are the signed-in family's real members, so a scanned document is attributed correctly. The AI key never leaves the server.
